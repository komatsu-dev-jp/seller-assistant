# Slack追加要望の再調査 v3

確認日: 2026-08-13（JST）  
対象: 画像加工、カテゴリ別採寸、月間収支、仕入先別分析  
状態: 関連モック再作成前。仕様・実装・Goalは未開始。

## 結論

1. 画像加工は、CodexやRPA（人のクリックを代行する自動操作）でPhotoroomのWeb画面を常時操作する方式を本番機能にしない。MVPは利用者自身のPhotoroom Proによる手動BatchとSKU付きZIPの再取込、正式な自動化はPhotoroom公式APIと書面での利用許諾確認を前提にする。
2. 採寸は「衣類で共通の固定項目」ではなく、カテゴリと形状で切り替わる版管理済みテンプレートにする。AIはカテゴリ、測定線、異常候補を提示するだけで、現物を人が測った値を正本にする。
3. 月間収支は、入金額、運用上の商品粗利益、直接費控除後の取引貢献利益、会計帳簿を混ぜない。仕入先分析は母数、観測期間、原価等のデータ充足率を必ず併記し、AIが仕入継続・停止を決めない。

## 1. 画像加工

### 採用する経路

#### MVP: Photoroom Pro手動Batch

1. 本アプリが原本を保持したまま、`SKU_連番`のファイル名で「加工用ZIP」を出力する。
2. 利用者が自分のPhotoroom Pro SpaceでBatch加工する。
3. 加工済みZIPを本アプリへ戻し、SKUと連番で自動照合する。
4. 原本と加工後を左右比較し、人が輪郭、色、ブランドロゴ、品質タグ、汚れ、傷を確認する。
5. 合格した加工後画像だけを出品候補へ進め、原本は上書きしない。

PhotoroomのBatchは複数画像へ背景、サイズ、位置等をまとめて適用できる。Pro以上で書き出せる。Freeアカウントは商用利用不可と案内されているため、販売用画像のMVP導線をFree前提にはしない。

- [Batch公式ヘルプ](https://help.photoroom.com/en/articles/11784338-what-is-the-batch-feature)
- [アプリ料金](https://www.photoroom.com/pricing)
- [Freeアカウントと商用利用](https://help.photoroom.com/en/articles/12523455-free-accounts-and-commercial-use)

#### 正式版候補: Photoroom公式API

API（アプリ同士が正式な窓口で通信する仕組み）では、Basicで背景除去、切り抜き、サイズ統一、白等の単色背景を扱える。PlusではAI背景、AI影、再照明、画像補正等が加わる。

- Basicの公開価格目安: 1枚0.02米ドル、月20米ドルから
- Plusの公開価格目安: 1枚0.10米ドル、月100米ドルから
- Pro契約とAPI契約・APIクレジットは別
- APIキーはiOS/Web画面へ埋めず、自社サーバーだけで保持
- 顧客向けSaaSへ組み込む権利は公開情報だけで断定せず、提供開始前にPhotoroomへ用途を説明して書面確認

- [API料金・機能比較](https://www.photoroom.com/api/pricing)
- [API料金ドキュメント](https://docs.photoroom.com/getting-started/pricing)
- [API OpenAPI仕様](https://docs.photoroom.com/api-reference-openapi)
- [Startup/API料金](https://www.photoroom.com/api/startup-plan)
- [Partner Plan](https://www.photoroom.com/api/api-partner-plan)
- [Enterprise契約](https://www.photoroom.com/legal/enterprise-services-agreement)

無料試用は、本番10回の背景除去と、透かし付きSandboxの案内がある。ただし背景除去の継続無料枠について公式ページ間に表現差があるため、料金画面の表示を正本にし、アプリの恒久的な無料枠として約束しない。

#### 本番中核にしない: Codex/RPAによるWeb画面操作

一時的な操作確認には使えても、製品の定期処理には採用しない。理由は次のとおり。

- 公式の連携窓口ではなく、UI変更、ログイン、CAPTCHA、セッション切れで停止しやすい。
- 利用規約はスクレイピング、通常の人が合理的に行える量を超える自動リクエスト、許可されていない手段によるアクセスを禁止している。
- Pro契約がAPI利用や代理操作を許可する根拠にはならない。
- 利用者のログイン情報、Cookie、二段階認証情報を当アプリが預からない。

- [Photoroom利用規約](https://www.photoroom.com/legal/terms-and-conditions)

### 加工レシピと安全確認

中古品の標準レシピは、商品そのものを生成変更しない処理に絞る。

- 背景除去
- 白背景
- 中央配置
- 余白10%
- 2000×2000px
- 必要時のみ弱い自然な影

公式の中古品向けチュートリアルにも、白背景、余白、中央配置、影を組み合わせる例がある。

- [中古品マーケット向け画像改善チュートリアル](https://docs.photoroom.com/tutorials/how-to-improve-images-for-second-hand-item-marketplaces)

AI背景、Flat Lay、Ghost Mannequin、再照明、テキスト除去、Expand、Beautifier等は、商品形状、ロゴ、傷や汚れを変えてしまう可能性がある。初期状態はOFFとし、有料の実験機能として使う場合も、原本比較と人の承認を必須にする。

### データの扱い

- 自社DBと非公開オブジェクトストレージを正本にし、原本、加工後、サムネイルを別ファイルとして保存する。
- EXIFの位置情報等は加工用コピーから除去する。
- Photoroomへ送った処理ID、レシピ、日時、操作者、承認者、出力ハッシュを監査ログに残す。
- APIの保存・学習利用について公式の利用規約、Privacy、Securityページに読み取り差がある。学習利用拒否設定を有効にし、公開前に書面確認する。

- [Security](https://www.photoroom.com/platform/security)
- [Privacy Policy](https://www.photoroom.com/legal/privacy)

### 無料・有料の差

| 無料 | 有料 |
|---|---|
| 原本保管、手動の切り抜き/回転/サイズ調整、加工用ZIP書出し、加工済ZIP再取込、原本比較 | 公式API許諾後の背景除去・白背景の自動処理、優先キュー、処理回数枠、チーム承認、再処理、監査の長期保存 |

Photoroom API費用を恒久的な無制限無料機能へ含めない。APIの従量費は利用量計に表示し、契約条件確定後にプランごとの画像枠を決める。

## 2. カテゴリ別採寸

### 正本と共通記録

人が現物を平置きで測った値を正本にする。AIはカテゴリ候補、測定線、入力ミス・異常候補を示すだけで自動確定しない。

1項目ごとに次を保存する。

- `definition_id`と定義バージョン
- 数値と単位
- 平置幅、一周、直線、縫い目沿い等の基準
- 未伸張、ボタンを閉じた状態等の測定状態
- 測定者と測定日時
- 測定線が見える証拠写真
- 測定回数、承認者、差戻し理由

画面上の「必須」は本アプリ内で採寸完了にする条件であり、各販売チャネルの必須入力という意味ではない。

### MVPテンプレート

| カテゴリ | アプリ内の必須候補 | 任意・条件付き |
|---|---|---|
| トップス・シャツ | 肩幅、身幅、着丈、袖丈 | 首周り、袖幅、袖口幅、裾幅。ラグランは肩幅・袖丈を対象外にし、裄丈へ切替 |
| ジャケット・コート | 肩幅、身幅、着丈、袖丈 | 裄丈、裾幅、袖口幅、重量、前丈・後丈 |
| パンツ | ウエスト平置幅、股上、股下、わたり幅、裾幅 | ヒップ幅、脇丈、膝幅、ゴムの自然時・最大時 |
| スカート | ウエスト平置幅、スカート丈 | ヒップ幅、裾幅、ウエスト最大値、前丈・後丈 |
| ワンピース | 身幅、総丈、該当時の肩幅・袖丈 | ウエスト幅、ヒップ幅、裄丈、裾幅、前丈・後丈、ストラップ範囲 |
| オールインワン | 身幅、総丈、ウエスト幅、股下 | 股上、ヒップ幅、わたり、裾幅、肩幅・袖丈、ストラップ範囲 |
| ニット | 自然状態の身幅、着丈、袖丈または裄丈 | 肩幅、裾幅、袖口幅。伸長時寸法はMVP対象外 |
| 靴 | タグ表記サイズ、アウトソール全長・最大幅 | ヒール高、厚底高、ブーツ筒丈・履口。内寸は任意 |
| バッグ | 幅、高さ、マチ | 持ち手長・立ち上がり、ショルダー最小・最大、重量 |
| 帽子 | タグサイズと内周または調整範囲 | 高さ、深さ、つば |
| アクセサリー | サブタイプ別 | ネックレス等の全長、トップ寸法、リング号数、ベルト穴範囲等。MVP後半 |

未対応カテゴリでも「カスタム採寸名＋値＋単位＋証拠写真」で止まらないようにする。

### ガイドと再測定

- 水平な台、正面、しわを軽く整えた状態を共通ルールにする。
- 測定線を1本だけ太く表示し、始点・終点と「直線」「縫い目沿い」「平置幅」「一周」を文章でも示す。
- ウエスト等の平置幅と一周は別項目にする。幅×2は「概算」と明示し、人の確定値を上書きしない。
- `0以下`、最小値が最大値を超える、必須値欠落は保存を止める。
- 同じ項目の2回差が衣類・バッグ・帽子で2cm超、靴・小物で0.5cm超なら暫定の要確認にする。これは各社が案内する手計測差を基にしたプロダクト仮説であり、実データで調整する。
- 股下が総丈以上、靴幅が靴長以上、cm/inch混在等は警告する。理由付き保存は可能にする。
- AI推定との差だけで人の値を否定しない。

## 3. 月間収支と仕入先別分析

### 画面で分ける金額

| 指標 | 初期定義 |
|---|---|
| 売上（運用） | JSTの対象期間内に取引完了した商品の最終販売額。完了前キャンセルは0 |
| 返金 | 期間内に返金確定した商品代金。手数料返還は販売手数料のマイナスで別記録 |
| 正味売上 | 売上－返金 |
| 商品粗利益（運用） | 正味売上－対応SKUの配賦済み取得原価。販売手数料・送料は引かない |
| 実現粗利率（運用） | 商品粗利益÷正味売上。正味売上が0以下なら「—」 |
| 取引貢献利益 | 商品粗利益－販売手数料－出品者負担送料－梱包費－返品関連費 |
| 入金 | 販売チャネルから実際に精算された額。売上発生月と混ぜない |

`取引貢献利益`は運用指標であり、会計上の営業利益、事業所得、税額ではない。画面に固定注記する。

### 仕入先別に見る指標

- 仕入点数と総取得原価
- 平均仕入単価 = 仕入バッチ総取得原価÷検収済み点数
- 平均販売単価 = 取引完了売上÷取引完了点数
- 商品粗利益と実現粗利率
- 販売率 = 返品されていない売却済み点数÷検収済み仕入点数
- 30日、60日、90日の販売率
- 在庫回転率（原価） = 期間売上原価÷平均在庫原価
- 在庫日数 = 平均在庫原価÷期間売上原価×期間日数
- 売切日数の中央値とP75
- 返品率、キャンセル率、加重値下げ率
- 期末在庫原価と在庫年齢帯

仕入月コホート（同じ時期に仕入れた集団）と販売月の月次損益を混ぜない。画面には基準日と観測日数を表示する。

### 欠損と照合

- 欠損を0にしない。`—`、`原価未配賦`、`送料未確定`、`返品期間未満`、`n<10参考値`等を表示する。
- 母数n、原価充足率、チャネル精算データ充足率、最終同期日時を常に表示する。
- 未販売SKUの原価は当月費用にせず在庫へ残す。
- 過去月販売の当月返品は「過去月返品調整」に分ける。
- 運用集計と会計帳簿の間を、期間差、返金差、未配賦、在庫調整、手入力で照合する。
- SKU、注文、証憑、仕訳候補の参照IDを相互にたどれるようにする。

国税庁の手引きでは、売上原価は期首棚卸高＋年間仕入高－期末棚卸高で計算し、売上済み未入金と前受金を区別する。したがって販売チャネルの入金月を、そのまま会計売上月として扱わない。

- [国税庁 令和7年分 青色申告決算書の書き方（一般用）](https://www.nta.go.jp/taxes/shiraberu/shinkoku/tebiki/2025/pdf/025.pdf)
- [国税庁 個人で事業を行っている方の記帳・帳簿等](https://www.nta.go.jp/taxes/shiraberu/shinkoku/kojin_jigyo/index.htm)
- [国税庁 棚卸資産の評価方法の届出](https://www.nta.go.jp/taxes/tetsuzuki/shinsei/annai/shinkoku/annai/17.htm)
- [国税庁 所得税基本通達 棚卸資産](https://www.nta.go.jp/law/tsutatsu/kihon/shotoku/08/01.htm)

### AIと税務の境界

固定文言:

> 運用分析の参考値です。会計上の売上・利益・所得・税額を示すものではありません。

> この指標だけで仕入先の継続・停止を決めず、件数、観測期間、季節、商品構成を確認してください。

AIは事実の集計、計算式の説明、欠損・重複・異常候補の指摘、承認済みルールによる仕訳候補までにする。「停止すべき」「必ず儲かる」「この税区分が正解」「申告完了」等は表示しない。税区分、棚卸評価方法、最終仕訳、申告は本人または税理士が確定する。

## 4. 更新する関連モックだけ

- Mobile: 画像加工キュー、Pro手動Batch、ZIP再取込、原本比較、承認
- Web: 画像加工キュー、レシピ、失敗/再処理、API使用量、許諾状態
- Mobile: カテゴリ別採寸、測定線、平置幅/一周、再測定

既に承認済み方向のオンボーディング、仕入、出品引渡し、注文配送、チーム権限等のモックは再生成しない。
