# PC23→24 商品説明の一時保存失敗からの復旧パケット

状態：実装・自動検証・通常状態の右サイドパネル確認・独立再レビュー完了。一時保存拒否を意図的に起こした画面の目視だけは、サイドパネルの安全制約により未確認として残す。
開始日：2026-09-21 JST

## 解消する問題

公開確認版のPC24では、商品説明をブラウザー内へ一時保持できなかった場合に「先に商品説明をコピーしてください」と案内して戻る操作を止める。しかし、コピーに成功しても一時保存失敗の状態は解消されず、保存機能が復旧しても再編集しない限り戻れない。案内どおり操作しても先へ進めないため、現在の本文と補足メモを失わず、本人の再試行で安全に復旧できるようにする。

## 承認済み根拠

- `docs/implementation/all-pages-interaction-plan.md`：PC23→24の本文・補足メモ分離、未保存時の移動停止は実装済みで、一時保存拒否状態の実操作だけが未確認として残る。
- `docs/design/pc-web-redesign-prompts-v1.md`：PC23で本人が説明文を編集・確認し、PC24でコピーする流れを承認済み。
- `docs/specs/approved-ui-integration-addendum-v1.md`：P1機能をP0 gate前に勝手に有効化しない。今回の修正は既存のブラウザー内一時保存だけを扱う。
- 現行コードではコピー成功が `descriptionCopyStatus` だけを変更し、`descriptionDraftStatus` を解消しないため、戻る操作が永久に止まる経路がある。

## リスクと担当

- リスク：中程度。外部送信・共有保存はないが、編集内容の消失防止と画面遷移を扱う。
- 実装運転モード：`astra-centric`。
- 実装担当：別実行の `gpt-6-astra` / low / `description_draft_recovery_impl` を唯一のsource writerとする。
- 確認担当：実装担当とは別実行の `gpt-6-astra` / lowによる読み取り専用レビュー。ルート担当が対象テスト、全体check、右サイドパネルの実ブラウザー確認を行う。
- モデル切替ゲート：既存UIとsessionStorageだけの限定状態復旧なのでAstra lowでGO。API、DB、実商品保存、未承認のデータ破棄、標準ブラウザー履歴の全面制御が必要になった場合は変更を広げずルートへ戻す。

## 実装内容

- PC23の一時保存失敗案内に、現在の本文と補足メモを同じsessionStorageへもう一度保持する明示的な再試行操作を設ける。成功時だけ失敗状態を消し、通常どおりPC24へ進める。
- PC24の一時保存失敗案内にも再試行操作を設ける。戻る操作自体でも現在の本文と補足メモを再保存し、成功した場合だけPC23へ戻る。失敗が続く場合は遷移を止める。
- コピー成功は一時保存成功と混同しない。コピー後に本文を変更した場合、古い本文のコピー成功を最新編集の退避済み状態として使わない。
- 読み取り・書込み拒否が続く場合でも、画面内の本文と補足メモを保持し、保存済みと表示しない。

## 受け入れ条件

1. 保存拒否時も本文・補足メモを画面内に保持し、保存済みと表示しない。
2. PC23の再試行または次へ、PC24の再試行または戻るで現在値を再保存し、成功時だけ通常遷移できる。
3. 保存不可が続く場合は遷移を止め、コピー成功を保存成功として扱わない。
4. コピー失敗、コピーの遅い応答、コピー後の再編集で、最新本文の保存状態を誤判定しない。
5. リセット取消で本文・補足メモを保持し、失敗時に保持成功を表示しない。
6. 通常のPC23→24→23で本文・補足メモの分離と保持を維持する。
7. 1536pxと768pxで失敗案内・再試行・戻る操作の切れ、重なり、横はみ出しが0。キーボード操作と読み上げ名がある。
8. 外部通信、API、DB、localStorage、実商品保存を追加しない。

## 検証

- 保存領域取得拒否、書込み拒否、拒否解除後の再試行、コピー成功／拒否／遅延、コピー後再編集、戻る再試行、リセット取消、本文とメモの分離を動作テストで確認する。
- 対象Vitest、Web型確認、ESLint、Prettier、`npm run check`、`git diff --check`を合格させる。
- Codex右サイドパネルのPC23／24を1536×1024と768×1024で操作し、通常系と保存拒否→復旧、横はみ出し0、操作部品の重なり0、console error / warning 0を確認する。
- 凍結差分を実装担当とは別実行のAstra lowが元要件・コード・テスト・画面証拠から確認する。

## 実行結果

- PC23／24へ明示的な再試行を追加し、PC24の戻るでも保存成功時だけ遷移するようにした。コピー成功と一時保存成功を分離し、コピーの遅延応答やコピー後の編集で古い成功表示を復活させない。
- 初回独立レビューで、初回の読取拒否後に既存本文とメモを初期値で上書きし得るP2を検出した。保存なしと読取不可を分離し、読取不可中は編集・リセット・PC24コピーを止め、復旧時に既存内容を先に読み直すよう修正した。
- 対象4ファイル・25テスト、最終`npm run check`（112 test files／841 tests、全gate、86 routes build）、`git diff --check`を合格した。
- 右サイドパネルでPC23→24→23の本文・補足メモ保持、コピーのクリック／Enter操作、コピー後編集による古い成功表示の解除を確認した。1536×900／768×900で横はみ出し0、画面外操作0、見出し・入力・ボタンの重なり0、console error／warning 0だった。
- 一時保存拒否そのものをブラウザー上で強制する操作は安全制約により行わず、取得拒否・読取拒否・書込拒否・復旧は25テストで確認した。独立再レビューはP1=0、P2=0、P3=0で合格した。
- 証拠は`output/playwright/live-pc23-description-draft-recovery-evidence.md`。

## 停止・昇格条件

- 既存の保持方針を変更する必要、実商品保存、未確認内容の破棄、API／DB、P1新機能が必要になった場合は停止する。
- sessionStorage拒否を越えて標準ブラウザーの戻る・タブ終了を全面保証する変更へ広げない。
- 原因不明の失敗、対象外ファイルとの競合、承認デザインを崩す必要が出た場合は証拠と再開条件をhandoffへ残してルートへ戻す。
