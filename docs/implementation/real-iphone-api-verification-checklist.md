# 実iPhone・実API確認の開始手順とチェック表

## 結論

この確認は、GitHub Pagesの画面見本ではなく、PC内のAPI・PostgreSQL・非公開写真保存へつながる現在の実装をiPhoneから操作するためのものです。APIは、画面から受け取った操作を確認してDBへ渡す、このアプリ自身の処理窓口のことです。外部企業のAPIや有料サービスへは接続しません。

- 費用: 0円
- 公開インターネット接続: なし
- 利用範囲: 同じ信頼済みWi-Fi内のPC 1台と、許可したiPhone 1台だけ
- 確認URL: 起動後の`https://<PCのWi-Fi IP>:4274/login`
- 現在の状態: `WAITING_HUMAN`

現時点ではiPhoneのIPアドレス、機種、iOS版、実際の到達確認がないため、使えるURLを推測して案内しません。値がそろい、下記の0〜4が合格した時点で、その回だけのURLを案内します。

## 0. 始める前にそろえるもの

| 必要なもの     | 条件                                 | 未確認ならどうするか               |
| -------------- | ------------------------------------ | ---------------------------------- |
| PCとiPhone     | 同じ家庭内などの信頼済みWi-Fi        | 共有Wi-Fiでは開始しない            |
| iPhoneのIP     | 設定→Wi-Fi→接続先の情報→IPv4アドレス | Codexへその値だけ伝える            |
| 機種・iOS版    | 例: iPhone 15 / iOS 18.x             | チェック表へ記録する               |
| 試験データ     | 架空の商品・住所・金額だけ           | 実住所、実口座、実商品を入力しない |
| 試験アカウント | このPC内だけの専用アカウント         | 実サービスのパスワードを使わない   |
| PostgreSQL     | 今回の追加更新0040を含む使い捨てDB   | production DBや既存DBを使わない    |
| 写真保存先     | `C:\tmp`内の専用非公開フォルダー     | Git、Pages、Slackへ保存しない      |
| HTTPS証明書    | その回だけのローカル証明書           | 秘密鍵をiPhoneへ渡さない           |

## 1. PC側の起動契約

詳しい証明書と接続制限は[同じWi-Fi内のiPhoneで安全に表示する手順](secure-lan-preview-guide.md)を優先します。次の値は`.env`、Git、Slack、Notionへ保存せず、起動中のターミナルだけへ設定します。

### APIをPC内だけで起動

設定する値:

- `DATABASE_URL`: `resale_app_runtime`を付与した、管理者ではない試験用DB接続先
- `SESSION_SECRET`: その回だけの32バイト以上の乱数
- `ADDRESS_ENCRYPTION_KEY`: その回だけの32バイト暗号鍵
- `LOCAL_MEDIA_ROOT`: `C:\tmp`内の試験写真フォルダー
- `APP_ORIGIN`: `https://<PCのWi-Fi IP>:4274`
- `PORT`: `3200`

起動コマンド:

```powershell
npm.cmd run dev:api
```

合格条件は、APIが`127.0.0.1:3200`だけで待ち受け、管理者DB接続、秘密値不足、未知の画面URLでは起動または変更操作を拒否することです。

### WebをPC内だけで起動

設定する値:

- `API_INTERNAL_ORIGIN`: `http://127.0.0.1:3200`
- `APP_ORIGIN`: `https://<PCのWi-Fi IP>:4274`

起動コマンド:

```powershell
npm.cmd run dev --workspace @resale/web -- --port 4273
```

合格条件は、Webが`127.0.0.1:4273`だけで待ち受け、WebからAPIへの中継先が`127.0.0.1:3200`だけであることです。

### iPhone 1台だけへHTTPS中継

設定する値:

- `LAN_PREVIEW_BIND_HOST`: PCのWi-Fi IPv4アドレス1件
- `LAN_PREVIEW_ALLOWED_CLIENT_IP`: iPhoneのWi-Fi IPv4アドレス1件
- `LAN_PREVIEW_HTTPS_PORT`: `4274`
- `LAN_PREVIEW_CA_PORT`: `4275`
- `LAN_PREVIEW_UPSTREAM_ORIGIN`: `http://127.0.0.1:4273`
- `LAN_PREVIEW_CERT_PATH`、`LAN_PREVIEW_KEY_PATH`、`LAN_PREVIEW_CA_CERT_PATH`: `C:\tmp`内のその回専用ファイル

起動コマンド:

```powershell
npm.cmd run lan:preview
```

開始前に確認する待受先:

| ポート | 正しい待受先     | 誤り                    |
| -----: | ---------------- | ----------------------- |
|   3200 | `127.0.0.1`      | `0.0.0.0`やPCのWi-Fi IP |
|   4273 | `127.0.0.1`      | `0.0.0.0`やPCのWi-Fi IP |
|   4274 | PCのWi-Fi IP 1件 | `0.0.0.0`               |
|   4275 | PCのWi-Fi IP 1件 | `0.0.0.0`               |

Windows Firewallも、4274・4275を許可したiPhoneのIP 1件だけに限定します。上記のいずれかが違えばURLを案内せず停止します。

## 2. iPhoneで最初に行うこと

1. Safariで`http://<PCのWi-Fi IP>:4275/resale-ops-local-preview-ca.cer`を開き、公開CA証明書だけを取得します。
2. 設定→一般→VPNとデバイス管理で`Resale Ops Local Preview CA`をインストールします。
3. 設定→一般→情報→証明書信頼設定で同CAを信頼します。
4. Safariで`https://<PCのWi-Fi IP>:4274/login`を開きます。
5. 架空の試験アカウントでログインします。

秘密鍵のファイル、フォルダー一覧、別端末からの接続は表示されないのが正しい結果です。警告や項目名が説明と違う場合は先へ進まず、その画面のスクリーンショットだけを返します。

## 4. 即時停止する条件

- `0.0.0.0`で待ち受けている
- 許可していない端末から画面が開く
- GitHub Pagesや外部URLへ実データを入力する必要がある
- 管理者DB接続でAPIが起動している
- Safariに証明書警告が残る
- 固定の時刻・電池表示がWeb内に再び出る
- 写真、金額、在庫差異を人の確認なしで確定する
- `127.0.0.1`、PCの許可済みIP以外への自動通信がある
- 実住所、実口座、実サービスのパスワードが必要になる

停止した場合は、エラー文、機種・iOS版、日時、どの番号まで進んだかだけを記録します。新しい公開先、トンネル、外部API、認証緩和で回避しません。

## 5. 終了時

1. HTTPS中継、Web、APIの順に停止します。
2. iPhone限定Firewall規則を削除します。
3. iPhoneからローカルCA profileを削除します。
4. `C:\tmp`のその回専用証明書・秘密鍵・架空写真を、対象パスを確認してから削除します。
5. 結果表を`PASS`、`FAIL`、`WAITING_HUMAN`で更新します。

人が1〜18を実行し、端末から実際に到達できた証拠がそろうまでは、実iPhone確認も「全機能が反映された完成URL」も完了とは扱いません。
