## 完了と数える条件

各画面は、次をすべて満たした場合だけ完了とする。

1. 画面番号、画面名、説明、主ボタン、戻る操作が正本と一致する。
2. カード、表、入力欄、写真枠、状態表示の並びと大きさが正本と一致する。
3. 白・薄灰、濃紺、コバルト青、緑、オレンジ、赤の用途が正本と一致する。
4. モバイルはiOS風の上部、角丸カード、44px以上の操作領域、固定フッター `ホーム / 作業 / 商品 / 在庫 / 会計` を維持する。
5. PCは承認画像どおりの左ナビ、上部バー、一覧と詳細の同時表示を維持する。
6. 主ボタンと戻るボタンで、承認順に全画面を移動できる。
7. 画像を画面全体へ貼るだけの実装にせず、文字、入力、ボタン、一覧をHTMLとして操作できる。
8. 外部API、外部CDN、自動ログイン、スクレイピング、RPA、有料サービスを追加しない。
9. 公開レビューでは架空データだけを使い、保存・公開・在庫変更・会計確定が動くように見せない。
10. 実運用画面では既存の権限、人の確認、監査、二重読取、安全な手入力fallbackを失わない。

## 比較方法

- モバイル: 390×844 CSS pixelで1画面ずつ撮影する。
- PC: 1440px幅で1画面ずつ撮影する。
- 正本画像と横に並べ、見出し、余白、主要カード、ボタン、ナビ、状態色を確認する。
- 意図的な差は、実データの値、ブラウザ標準フォントの字形、端末のステータスバーだけに限定する。
- 差がある画面は「未完了」に戻し、次の機能へ進まない。
