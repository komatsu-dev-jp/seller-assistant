# 箱の受取から検品・見込み粗利まで

2026-10-03。利用者の今回の依頼を実装する。既存の白・青のモバイル基準を再利用し、3案の再承認や別の企画は行わない。

## 原因と完成条件

既存box-02の確定ボタンはsessionStorageのconfirmedCountを書くだけで、商品登録へ進まない。box-03以降は固定見本のまま。これを同じ箱・商品を引き継ぐ操作へ置き換える。

- 箱の名前・仕入代・仕入時の送料・点数を入力し、確定すると1点目の簡単登録へ進む。
- 商品名・ブランド・サイズ・状態・検品結果・気になる点を入力。保存して次の商品へ進める。登録後の相場確認はその場でも、箱の商品一覧から後でもできる。
- 本人が販売済みの類似商品のURL・価格・比較メモを登録する。確認済みの販売事例だけを候補へ使い、同じURLを二重計上しない。
- 確認済み事例の安い価格を候補として提示するが、見込み販売価格の採用は本人のボタン操作による。
- 見込み粗利 = 見込み販売価格 − 箱の取得費を点数で配分した額 − 販売手数料 − 発送送料 − 梱包代。円の配分余りは先頭から1円ずつ、手数料の円未満は概算として切り上げる。空欄を0円扱いしない。販売不可の確認済み商品は売価0円・配分原価の損失として扱う。
- 箱の一覧に登録済み・要確認・計算済みを示す。全点計算前は箱全体の利益を確定表示しない。赤字も隠さない。
- 複数の箱と各商品の入力は、このブラウザーの専用localStorageに保存する。既存の見本1点や会計設定は変更しない。再読み込み・別画面からの再開・JSONの控え保存に対応。
- 保存拒否・容量不足・古いタブからの書込みは失敗として表示し、入力を画面に保持。失敗時に次へ進まない。
- 同時書込みによる消失を防ぐため、箱の編集は同じブラウザー内で1タブのみ許可する。Web Locksの排他ロックを取得してから読込み、閉じたときに解放。別タブ編集中・未対応環境では保存内容を変更せず案内し、再試行できる。
- 旧box-01〜05のURLと商品一覧から、この実装へ入れる。0点で確定できない。巨大な固定操作バーを追加しない。

## 境界

ブラウザー内での入荷記録と見込み計算まで。販売事例は本人入力と公式ページへの明示リンク。外部の情報取得、スクレイピング、有料API、自動出品、会計確定、端末間共有は追加しない。見本データを実在商品として生成しない。写真・採寸・出品準備の既存見本商品へ実入荷品を混ぜない。今後の連結は商品IDを保持する設計で扱う。

メルカリの通常販売手数料10%を初期値として変更可能にする。他の販売先や特別な配送等は本人が率を確認する。参考：https://help.jp.mercari.com/guide/articles/65/ （2026-10-03確認）。事例から販売成立や利益は保証しない。
