# 箱の検品登録：ブランド選択と商品名の自動作成

## 目的と受入条件

ユーザー依頼（2026-10-04）：ブランドを別画面で検索・絞り込み、サイズは選択式、対象・種類・袖・色を登録し、商品名をまとめる。

- ブランド選択専用ビュー `box-02/?box=…&step=brand&item=…` から同じ商品に戻る。ブラウザーの戻る・再読み込みでも商品を維持する。
- 日本語／英語検索、登録で使ったブランドの絞り込み、一覧外の名前・ノーブランドを選べる。
- サイズ・対象・種類・袖・色は選択式。特殊サイズは手入力できる。不明な項目は必須にしない。
- 商品名は `ラルフローレン 半袖シャツ レディース ネイビー M` の順に作成。直接修正した名前は自動上書きせず、明示操作で自動作成へ戻せる。
- 保存済みv1は厳密に検証しv2へメモリ内移行。既存名を手入力扱いで維持し、費用・販売事例・IDを変えない。成功した保存まで元の記録を書き換えない。
- 保存失敗・同時編集禁止・見込み粗利計算を維持。ブランド検索に外部APIを使わない。出品を自動実行しない。
- 長い合成名はv2の下書きとして500文字まで保存し、登録前に100文字へ短くする説明を表示する。v1の100文字検証は維持。ブランド画面から戻れない状態にしない。

## 範囲と検証

変更範囲：box-intake store/flow/CSS、offline options、関連テスト、作業記録のみ。既存承認画面と白／青のデザインを再利用し全面変更しない。

検証：選択から登録・名前合成、手入力維持、サイズ例外、ブランド復帰、保存失敗、v1移行と壊れた記録の拒否。全体 `npm run check` とGitHub Pages用buildを実行。ブラウザー利用不能なら実画面検証済みと記載しない。

モデル割当：親が共有ファイルを単独実装。独立した新規Astra実行で読み取り専用レビュー（移行・入力保持・画面遷移中心）を行う。単一の小規模変更で並列実装の競合を増やさない。

参照：`AGENTS.md`、`apps/web/AGENTS.md`、`memory/INDEX.md`、`docs/DECISIONS.md`、`docs/implementation/box-intake-profit-packet.md`、`handoffs/active/2026-10-03-box-intake-profit.md`、既存box-intake source/testと承認済みmobile部品。利益計算や保存失敗に波及したら変更を広げず元の境界と回帰テストへ戻す。
