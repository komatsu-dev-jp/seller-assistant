# 販売状況を本人の手入力で保存する実装パケット

状態：完了。承認済みの手入力と再表示だけを実装・検証済み。

完了日：2026-09-21 JST

## 解消する問題

実運用の `/workflow` では、本人が登録済みの個人メルカリ商品ページを開いて販売状況を確認できるが、確認した数字と次回確認日を商品ごとに保存・再表示できない。PC26は承認デザインを確認する架空データ画面であり、実商品へ保存してはならない。このため、公開商品URLを登録済みの実SKUだけに、本人確認済みの販売状況を追記保存する。

## 承認済み根拠

- `docs/design/pc-web-redesign-slack-revisions-v2.md` のPC07：本人が公式ページを開き、価格、閲覧、検索、いいね、値下げ依頼を入力する。確認日と次回確認予定を残す。
- `docs/design/pc-web-redesign-prompts-v1.md` の画面26：出品日数、現在価格、閲覧、いいね、値下げ依頼、確認日、入力元を表示し、「入力内容を保存」する。
- `docs/DECISIONS.md` の2026-08-27：PC07 v2は利用者の「問題なし」で固定済み。自動取得、スクレイピング、Cookie共有、RPA、自動ログインを行わない。
- `docs/implementation/all-pages-interaction-plan.md`：商品URL保存とPC26のローカル画像表示は完了し、販売状況の数値保存は未完了として残っている。

## 今回の固定範囲

- 認証済み `/workflow` のうち、個人メルカリの公開商品URLを登録済みの実SKUだけを対象にする。PC26の架空6商品はDBへ接続しない。
- 本人が公式ページを見て入力する。入力元は `official_page_human_checked` に固定し、画像比較、OCR、自動取得を接続しない。
- 保存項目は、出品日数、現在価格、閲覧数、検索数、いいね数、値下げ依頼数、確認日、入力元、次回確認日とする。
- 6つの数値は空欄と0を区別し、空欄を0へ補完しない。整数以外、負数、安全な上限を超える値を拒否する。金額は円の整数であり、成約額・売上・会計事実として扱わない。
- 承認済み文書にない必須条件は追加しない。数値6項目は未確認なら空欄を許す。確認日と次回確認日は追跡漏れ防止のため保存時に必要とし、暦として存在する日付だけを許す。
- 記録は追記専用とし、既存記録を更新・削除しない。GETは最新記録と記録件数を返し、DB試験で過去記録が残ることを証明する。
- 確認者と保存日時はサーバー側で確定する。画面では内部UUIDを見せず、確認者を初心者にも分かる「ログイン中の管理担当」と表示する。同じ再送キーと同じ内容は同じ結果を返し、異なる内容は409で止める。
- 保存しても注文、発送、在庫、成約額、粗利、会計CSV、公開商品URLを変更しない。
- URL、画像、ファイル名、個人情報、入力した数値全文を監査へ複製しない。外部通信は行わない。

## リスクと担当

- リスク：重大。新規migration、認証済みAPI、workspace分離、追記履歴、再送制御、実運用Webを横断するため。
- 実装運転モード：`astra-centric`。
- 実装担当：別実行の `gpt-6-astra` / medium / `sales_check_persistence_impl` を唯一のsource writerとする。
- 確認担当：実装担当とは別実行の `gpt-6-astra` / medium による読み取り専用レビュー。ルート担当が自動試験と右サイドパネルの実ブラウザ確認を行う。
- コスト判断：定型抽出だけの追加担当は増やさず、DB・権限・再送を一つの担当へまとめ、統合の手戻りを抑える。実費とトークン消費は取得できないため未計測とする。

## 受け入れ条件

- 契約：6数値の空欄と0を区別し、負数、小数、指数表記、不正な区切り、上限超過、不正日付、余分な項目、許可外入力元を拒否する。
- DB：workspace分離、SKU複合FK、管理権限、公開商品URL登録済み、追記専用、再送キー一意、保存と監査の同一transaction、RLS、更新・削除禁止。
- API：未認証401、workspace不一致403、非管理者403、他SKU／URL未登録404または契約どおりの停止、不正入力400、異なる再送409、サービスなし503。同一再送は行・監査を増やさない。
- 不変条件：複数回保存で過去記録を残す。出品価格を保存しても成約額・利益・発送・在庫・会計CSVは不変。監査へURL・画像・個人情報・入力値全文を複製しない。
- Web：読込中、URL未登録、初回入力、保存中、失敗、保存済みを区別する。保存後GETとページ再読み込みで9項目、確認者、保存日時、履歴件数が一致する。SKU切替・遅い応答・保存中切替で別商品を混ぜない。
- 失敗復旧：503、応答喪失、同一再送、保存成功後GET失敗から、重複記録を作らず再確認できる。
- ブラウザ：Codex右サイドパネルで1440pxと390pxを操作し、保存、再読み込み、失敗復旧、横はみ出し0、重なり0、console error 0を確認する。外部メルカリページは開かない。
- fresh/upgrade PostgreSQL、対象テスト、`npm run check`、`git diff --check`、別実行Astra mediumの独立レビューを合格させる。

## 停止条件

- 項目の意味・必須性・権限について承認文書間の矛盾が判明した場合は、独自判断で変更せずルートへ戻す。
- 商品URL訂正、画像由来の記録、他販売先、会計・注文・発送状態の変更、既存データの書換えが必要になった場合は範囲を広げない。
- migration番号重複、対象外ファイルとの競合、原因不明のDB失敗、既存互換性の破壊を検出した場合は、証拠と再開条件をhandoffへ残して停止する。
