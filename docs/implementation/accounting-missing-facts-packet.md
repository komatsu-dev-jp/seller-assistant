# 発送後に不足金額を入力して会計へ進む修正案

状態：設計レビュー待ち。実装済み・利用者承認済みとは扱わない。
確認日：2026-09-20 JST

## 解消する問題

現行の注文登録では販売手数料と梱包費を入力しない。発送後の会計は主要な金額がそろうまで停止するが、足りない金額を追加するAPIと画面がない。販売金額も既存追加APIでは発送前に限定されるため、未入力で発送すると同じ問題になる。

## 正本と境界

- `../specs/goal-contract-revised-a-v2.md` のP0 10〜12、検証条件3：同じ商品・注文から収益とCSVまで追跡する。
- `../DECISIONS.md` の2026-09-03「未入力の販売事実を0円にせず」：不足時の会計停止を維持する。
- `apps/api/src/order-repository.ts` の `recordSaleAmount` は発送前専用。既存APIの状態制約を単純に外さない。
- 既存の会計権限はowner/accounting。shippingや外注へ金額を返さない。権限拡張は行わない。
- この案は初回の不足補完だけ。既存金額の上書き、返金確定、税務自動判断、過去CSVの書換えは含めない。

## 実装前に満たす設計条件

- [ ] 発送済み現行登録注文について、販売額・手数料・梱包費の「未入力」「記録済み」を返す読取契約を追加する。0円と未入力は別表示。
- [ ] 未記録の項目だけ、原資料の説明・発生日時・金額・人の確認を添えて追記する。空文字の数値変換は禁止。販売額は正、費用の明示0は許可。
- [ ] 原価と送料の既存根拠・税区分との整合を検証する。既存金額・税区分を画面初期値で推測しない。
- [ ] 注文・事業所・現物が一致し、対象状態が許可された場合だけ保存する。返金や返品の扱いが未確定ならその注文は理由付きで停止し、勝手に新たな会計方針を作らない。
- [ ] 同じ項目の同時登録・異なる内容の再送を拒否する。正常な再送は同じ結果を返す。トランザクションとDB側制約、監査履歴を用意する。
- [ ] CSV作成・再出力との競合を同じロック規約で防ぐ。すでに出力対象となった記録を変更しない。
- [ ] 保存後に金額の読取と会計チェックを再実行する。保存失敗・再送不明・注文切替時に古い金額でCSV作成しない。

## 独立設計レビュー結果（2026-09-20）

実装開始は保留。以下は調査済みの事実と、未承認の提案を分けて記録する。

- 現行注文登録UIの税区分はunknownであり、原価と送料にも残る。CSVはunknownを拒否する。不足3金額だけを追記してもCSVまで完走しない。
- 会計候補変換は0以下を拒否する。明示0円の費用を保持する方針とCSV生成を整合させる必要がある。
- 利用者へ「元記録を残す税区分の本人確認履歴」と「0円は記録を残しCSV仕訳行を作らない」方針を質問した。回答待ちであり、採用済みではない。
- DBの財務イベントINSERT権限は既存実行ロールにある。権限追加ではなく、対象注文・本人・有効会員・会計権限をDBでも検証する必要がある。
- 現行注文だけを対象に不足補完記録の一意性とイベント参照を設ける。legacy全体へ金額種別の一律一意制約をかけない。
- 既存送料挿入は発送処理専用。不足補完から追加・置換しない。
- ロック順は事業所→注文→対象事実。CSV作成側も金額を読む前に同じロックを取る必要があり、会計repositoryを変更範囲に含める。
- 独立担当はまず利益再計算までの分割実装を提案した。ただし全体GoalはCSVまでを維持し、分割パケット成功を全体完成としない。

## 追加凍結監査（2026-09-21）

結論はNO-GO。現時点で実装を開始しない。

- 正の販売手数料・梱包費は、専用の追記契約を設計すれば利益再計算へ反映できる。ただし税区分と0円方針が未決定のため、会計CSVの409は完全には解消しない。
- 既存の `recordSaleAmount` は発送前専用であり、この状態制約を外さない。発送後に販売額を追加すると、発送時の販売額スナップショットが古くなり、`shipping_sale_basis_snapshot_is_current` と写真事前確認が不一致になる。
- 現行の後追い販売額権限はowner/inventory_managerで、会計不足補完に必要なowner/accountingと一致しない。既存APIの流用ではなく専用権限契約が必要。
- 追記事実の一意性、行レベル権限、監査、再送、ロック、CSV競合を保証する追加migrationが必要。既存migrationの書換えは行わない。

実装再開には次の利用者判断が必要。

1. 元の `unknown` 税区分を保持し、別の本人確認済み税区分履歴を追記するか。
2. 明示0円の費用事実は保存するが、CSV仕訳行は作らない扱いでよいか。
3. 発送後に高い販売額が判明しても、発送時の写真省略判断は当時の履歴として固定するか。
