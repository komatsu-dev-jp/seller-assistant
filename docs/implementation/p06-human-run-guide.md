1. Chromeで`http://127.0.0.1:4273/login`を開く。
2. ローカル検証専用アカウント`owner@example.test`でログインする。パスワードは実施時にCodexが案内したテスト専用値を使い、実サービスのパスワードを入力しない。
3. `http://127.0.0.1:4273/workflow`を開く。
4. `F12`でChrome開発者ツールを開き、`Ctrl+Shift+M`で端末表示を有効にする。Responsiveの幅を`390`、高さを`844`にする。
5. 計測終了まで同じChrome、同じ390×844表示を使う。

`127.0.0.1`は、このPC自身だけを示すアドレスである。WebとAPIの両方が`200`を返すことは開始前にCodexが確認済みである。

WARMUP完了後にChrome開発者ツールの「Network」を開く。

1. 録画ボタンが赤い状態であることを確認する。
2. `Preserve log`を有効にする。
3. ゴミ箱または消去ボタンでWARMUPまでの一覧を空にする。
4. Networkを開いたまま、画面の10商品pilot欄へ戻る。

通信記録は10商品runの開始前から最終商品の終了後まで止めない。別タブを開かず、販売サイトや検索サイトへ移動しない。

## 5. その場で停止する条件

次のどれかが1件でも起きたら、続きの商品へ進まずCodexへ連絡する。

- ページを再読み込みした、Chromeまたはサーバーを再起動した
- アプリ、API、DB、画像読込、保存でエラーが出た
- 次のfixture ID、写真role、属性、採寸項目または値が一致しない
- 必須画像が不足した、保存ボタンが不自然に有効または無効である
- 外部ページが開いた、`127.0.0.1`以外への通信が見えた
- 写真、採寸、属性、文章に訂正不能な誤りがある
- 利用者都合で中断する必要がある

停電、OSの強制更新、端末故障だけは、画面の理由付き「外部事故として無効化」を使う。それ以外の中断を外部事故として扱わない。
