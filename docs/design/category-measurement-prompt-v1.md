```text
Use case: ui-mockup
Asset type: 日本のリユース物販チーム向け業務アプリの、実装検討用モバイルUI画面ボード
Primary request: 商品カテゴリごとに人が現物を採寸し、証拠写真・担当者・再測定履歴まで残す一連のiPhone画面を、16:9の1枚に7画面で可視化する。

Input images: Image 1はスタイル参照のみ。既存の商品写真、文字、レイアウトを複製しない。白い作業面、薄灰の境界、濃いネイビー文字、青い主操作、琥珀の要確認、緑の完了、角丸カード、役割・引継ぎ・監査を一目で理解できるB「高速ワークベンチ」＋C「役割・承認・監査」のデザイン言語だけを継承する。

Scene/backdrop: 明るい白〜薄灰の16:9デザインボード。左上に大見出し「モバイル 08｜カテゴリ別採寸」、小見出し「現物を、人が1項目ずつ確認」。下部に小さく「必須＝アプリ内の採寸完了条件。各販売先の必須項目ではありません。」と正確に表示する。

Style/medium: 実装可能な高精細プロダクトUI。コンセプトアートではない。現代的なiOS業務アプリ、清潔、平面、読みやすい日本語、細い線画アイコン、白いカード、控えめな影。

Composition/framing: 正面向きで同じ縮尺のiPhone縦画面を約7台、上段4台・下段3台の整然としたグリッドに配置。端末は重ねない、斜めにしない。各端末上に「1. カテゴリ」「2. トップス」「3. スカート」「4. パンツ」「5. 小物テンプレ」「6. 計測値」「7. 再測定」と大きく表示。各画面は1目的だけに絞る。

Screen 1 — カテゴリ / サブタイプ選択:
- 画面見出し「カテゴリを選ぶ」、補足「形に合う採寸項目を表示します」。
- 2列グリッドの大きな選択カードで「トップス」「アウター」「パンツ」「スカート」「ワンピース」「靴」「バッグ」「帽子」を日本語ラベルと単純な線画アイコンで表示。
- 「トップス」を青枠で選択。下にサブタイプ「Tシャツ」「シャツ」「ニット」「ラグラン」をチップ表示。
- 小さな注記「必須＝アプリ内完了条件」。青い主要ボタン「採寸を始める」。

Screen 2 — トップス1項目ガイド:
- 画面見出し「1 / 4 肩幅」。ロゴのない架空ブランドのネイビー色Tシャツを平置きした簡潔な図。
- 肩の左右に青い始点・終点の丸、太い測定線、ラベル「始点」「終点」。案内「肩先から肩先まで、直線で測る」。
- 上部または下部に工程チップ「肩幅」「身幅」「着丈」「袖丈」。肩幅が選択中。
- 切替カード「肩線がない・ラグラン」→「裄丈に切り替える」。
- 追加操作「任意項目」「＋ カスタム追加」。青い主要ボタン「数値を入力」。

Screen 3 — スカート:
- 画面見出し「スカートの採寸」。ロゴのないネイビー色スカートの平置き図。
- 第一カードを青枠で選択し「ウエスト平置幅 34.0 cm」、横方向の一本線、説明「左右の端から端」。
- その下に別カード「ウエスト一周 68.0 cm」、周囲を回る線、説明「平置幅×2の参考値」。
- 幅と一周を色だけでなく、異なるアイコン・見出し・説明で明確に区別する。
- 第三カード「スカート丈 82.0 cm」、上端から裾までの縦線。ボタン「保存して次へ」。

Screen 4 — パンツ:
- 画面見出し「パンツの採寸」。ロゴのないネイビー色パンツの平置き図。
- 図上に4本の色分けしすぎない明瞭な線と日本語ラベル「股上」「股下」「わたり幅」「裾幅」。
- 下部に工程リスト「股上 28.0」「股下 72.0」「わたり幅 31.0」「裾幅 未入力」。完了3/4の進捗。
- 「裾幅」が琥珀の未入力。青い主要ボタン「裾幅を測る」。小さな「任意項目を追加」。

Screen 5 — 靴・バッグ・帽子のテンプレ一覧:
- 画面見出し「小物テンプレ」。3枚の大きなカードを縦に並べる。
- 「靴」カード: 必須「表記サイズ・全長・最大幅」、任意「ヒール高・筒丈」。
- 「バッグ」カード: 必須「幅・高さ・マチ」、任意「持ち手・ショルダー範囲」。
- 「帽子」カード: 必須「表記サイズ・内周 / 調整範囲」、任意「高さ・つば」。
- 各カードに線画の靴、バッグ、帽子。バッグを青枠で選択し、青い主要ボタン「このテンプレを使う」。下に「＋ カスタム項目」。

Screen 6 — 数値入力と証跡:
- 画面見出し「身幅を記録」。大きな数値入力「52.0」と単位セレクタ「cm」。
- 状態カード「平置き」「未伸張」「ボタンを閉じた状態」をチェック付きで表示。
- 証拠写真カード「測定線が見える写真」＋小さな衣類とメジャーのサムネイル、緑の「添付済み」。人物や手は描かない。
- 担当者カード「測定者：佐藤」「本日 14:32」。小さく「候補は参考、人が確認して確定」。
- 青い主要ボタン「人が確認して確定」。

Screen 7 — 再測定警告と監査:
- 上部に琥珀の状態ラベル「要確認」、大見出し「肩幅を再測定してください」。
- 比較カード「1回目 42.0 cm」「2回目 45.0 cm」「差 3.0 cm」。説明「2回の差が2cmを超えました（暫定ルール）」。
- 青い主要ボタン「再測定する」。副操作「理由付きで保存」。理由選択「伸縮素材」「測定位置」「その他」。
- 下部の監査ログに「佐藤 14:32 計測」「田中 14:36 再確認依頼」を表示。
- 最終状態は人だけが確定することが分かる文言「確認者が確定するまで未完了」。

全端末共通UI:
- 1画面1目的、主要タップ領域は44pt相当以上、太めの主要ラベルと十分な余白。
- 上部は戻る、画面名、商品番号「AP-2508-00421」、進捗。下部ナビは同じ順で「作業台」「商品」「＋」「注文」「その他」。選択中の「商品」だけ青。
- 白 / 薄灰 / ネイビーを基調に、青は主要操作、琥珀は警告、緑は確認済みに限定。状態を色だけで表さず、必ずアイコンと日本語ラベルを併記。
- 衣類と小物はロゴなし・架空ブランド・落ち着いたネイビー。測定図は写真よりも明快な実務用図解を優先。

Text: 主要日本語ラベル、数値、単位を正確かつ明瞭に描く。特に「ウエスト平置幅」「ウエスト一周」「裄丈に切り替える」「任意項目」「カスタム追加」「人が確認して確定」「理由付きで保存」「監査ログ」を読み取れる大きさにする。意味のないダミー文章、極小文字、文字化けを使わない。

Constraints: 横長16:9、7画面すべて表示、実装可能なUI、一貫した下部ナビ、人の現物採寸を中心にする。AIが確定するような表現を入れない。参照画像はスタイルのみ。

Avoid: 「AI自動確定」、AIが自動で採寸したと誤認させるUI、「LiDAR自動採寸」、レーザーや3Dスキャン、Mercariまたはメルカリの名称・ロゴ・赤いM、他社マーケットプレイスの名称・ロゴ、自動出品、透かし、実在ブランド、人物、手、人体計測、暗い背景、ネオン、過剰なグラデーション、斜め端末、3D遠近、端末の重なり、英語中心、同じ画面の重複、読めない極小文字。
```
