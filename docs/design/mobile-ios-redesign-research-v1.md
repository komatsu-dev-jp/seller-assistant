## 今回の利用者フィードバック

- 公開レビュー版が4画面だけで、検品、撮影、採寸を含む一連の流れを確認できない。
- 「証憑」「mapping」「profile」など、業務・技術の言葉がそのまま表示されて分かりづらい。
- フッターの「今日の確認」は、移動先なのか操作なのか分かりづらい。
- スマホ版を、見た目だけでなく操作方法もiOSらしくしたい。
- Slackで3案を比較し、採用後に全ページの高精度モックを確認したい。

## 現状確認

- GitHub Pagesの公開レビュー版は「今日の確認」「在庫現場」「棚卸差異」「会計候補」の4画面だけであり、P0の縦導線全体ではない。
- 実装済みWebには `仕入 → 撮影・採寸 → 出品準備 → 注文・発送 → 収支・会計` があるが、PC向け情報量のまま表示する箇所と、スマホ専用の撮影・格納画面が分かれている。
- 既存M01〜M14は機能範囲の確認には使えるが、1枚に複数工程が並び、初めて操作する人が「今どこで、次に何をするか」を把握しにくい。
- 「検品」は仕様上必要だが、現行スマホ実装では独立した分かりやすい工程として見えにくい。

## 2026-08-25に確認したApple公式方針

- [Design principles](https://developer.apple.com/design/human-interface-guidelines/design-principles): 必要な要素だけを置き、現在地と次の操作が分かる階層、慣れた操作、誤りから戻れる設計を重視する。
- [Writing](https://developer.apple.com/design/human-interface-guidelines/writing): 専門語を避け、短く、動詞を使ったボタン名にし、複数工程で言葉を統一する。
- [Inclusion](https://developer.apple.com/design/human-interface-guidelines/inclusion): 専門語が必要な場合は先に意味を示し、すぐ調べられるようにする。
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility) と [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons): 主要操作は原則44×44pt以上とし、色だけに頼らない。
- [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars): タブバーは上位画面への移動だけに使い、撮影や保存などの操作を混ぜない。短い単語と見慣れたアイコンを併用し、画面ごとに隠したり無効化したりしない。
- [Materials](https://developer.apple.com/design/human-interface-guidelines/materials): Liquid Glassはナビゲーションと操作部品の層へ限定し、本文カードへ乱用しない。
- [Sheets](https://developer.apple.com/design/human-interface-guidelines/sheets): 用語説明や場所選択など、今の画面に関係する短い作業をシートで表示し、閉じる・完了を明確にする。

## 3案で共通に固定すること

- 1画面1目的。主ボタンは原則1つにする。
- 検品、撮影、採寸を別画面にし、`検品 2/5` のように現在地を表示する。
- ボタンは「次へ」だけにせず、可能な場合は `写真を確認する`、`肩幅を保存する` のように次の結果を示す。
- 通常のフッター候補は `ホーム / 作業 / 商品 / 在庫 / 会計` とし、撮影・保存・追加は本文側、設定・ヘルプは上部のアカウントメニューに置く。
- 「今日の確認」はフッターから外し、ホーム本文の `今日やること` に変更する。
- Liquid Glass風の半透明表現は上部バー、下部タブ、カメラ操作などへ限定する。
- 主要操作44pt以上、本文17pt相当、文字拡大、明暗、色覚差に対応できる構造にする。
- 外注担当には原価、利益、購入者住所、税務情報を表示しない。
- AIや写真読み取りは `入力候補` と表示し、人が確認しない限り確定しない。
- 架空データだけをモックに使い、実在する住所、金額、商品、レシートを使わない。

## 表に出す言葉の置換

| 内部・専門用語 | 画面に表示する言葉 | 必要な補足 |
|---|---|---|
| 証憑 | レシート・領収書 | 帳簿の詳しい説明内だけ「会計の証拠書類」と補足 |
| OCR | 写真から読み取った内容 | `読み取り結果を確認` を操作名にする |
| SKU | 商品番号 | 内部IDは詳細欄へ隠す |
| InventoryUnit | 在庫番号 | `現物1点につく番号` と説明 |
| 原価配賦 | 仕入れ代を商品ごとに分ける | 計算方法は詳細シートへ |
| 原本写真 | 撮ったままの写真 | `加工前` と補足してよい |
| 派生画像 | 加工した写真 | 元写真を消さない説明を添える |
| AI候補 | 入力候補 | `アプリの提案・未確認` と状態表示 |
| profile | 会計の基本設定 | 申告・税区分をアプリが決めない |
| mapping | 会計の仕分けルール | 専門的な貸方・借方は詳細へ |
| CSV | 会計ソフト用ファイル | 初回だけ `CSV` を括弧で補足 |
| missing_candidate | 見つからない商品（仮） | `削除されません・見つかったら戻せます` を併記 |
| 棚卸差異 | 数が合わない商品 | 詳細画面で正式語を補足可 |
| 同期待ち | 送信待ち | `通信が戻ると送信` と表示 |
| 監査ログ | 操作履歴 | 誰が・いつ・何を確認したか |
| 二重読取 | 商品と棚を順番に読み取る | 読取画面は `商品 → 棚 → 確認` |
| preflight | 作成前の確認 | 停止理由を具体的に列挙 |
| batch / run / session | 今回の作業 | 技術的な識別子は詳細へ |

## 採用する型

- 大きな画面タイトル、iOSのグループ化リスト、短い説明、画面下の大きな主ボタン。
- 商品写真、検品箇所、測る線、保管場所写真を文章より先に見せる。
- 用語説明は `?` だけでなく、分かりやすいラベル `これは何？` からシートで開く。
- エラーは `無効です` ではなく、`商品番号の末尾まで入力してください` のように直し方を書く。
- 完了時は、保存できた内容と次の作業を1つだけ示す。

## 避ける問題

- PCの表をiPhone幅へ縮小する。
- 1ページへ検品、撮影、採寸、文章確認を縦積みする。
- 英語の見出し、内部状態名、略語を主見出しにする。
- タブバーに追加、撮影、保存などの操作を置く。
- 半透明カードを本文全体へ重ね、文字の読みやすさを下げる。
- アイコンだけで意味を伝える、色だけで状態を伝える。
