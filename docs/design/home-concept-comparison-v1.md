# ホーム画面3案の比較 v1

確認日: 2026-08-13（JST）

## 推奨

主軸のおすすめは B「業務管制塔」。承認済みの「高速ワークベンチ＋チームリレー」と最も一貫し、一人運用から外注運用まで同じ情報構造で拡張できるため。

ただし初心者の撮影担当にはA、オーナーの朝の確認にはCが適する。採用時は一つを標準ホームに固定し、他案の良い部分を役割別カードとして追加する。

## 比較

| 項目 | A 今日のガイド | B 業務管制塔 | C オーナーパルス |
|---|---|---|---|
| 最初の問い | 次に何をすればよいか | どこが滞り、誰が対応するか | 収益・在庫で何を確認すべきか |
| 主利用者 | 初心者、一人運用、撮影担当 | オーナー、管理者、外注チーム | オーナー、経理確認者 |
| PCの主役 | 今日の作業、続き、要確認 | 工程数、作業キュー、例外、担当 | 運用指標、在庫年齢、未解決 |
| iPhoneの主役 | 次の1作業 | 自分の担当と期限 | 今日の確認と主要指標 |
| 長所 | 最も迷いにくい | 全体管理と反復速度のバランスがよい | 経営状態と行動を結び付けやすい |
| 弱点 | 大量運用の全体像が弱い | 初心者には情報量が多い | 現場作業の開始導線が弱い |
| 無料版との相性 | 高い | 中 | 中 |
| 有料Teamとの差別化 | 中 | 最も高い | 高い |
| 主な安全策 | 1作業ずつ人が完了 | 例外・承認・監査を常時表示 | 運用値と会計・税務を明確に分離 |

## 各案の主要導線

### A 今日のガイド

`今日やることを見る → 最優先の作業を開始 → 不足を直す → 完了 → 次の作業`

### B 業務管制塔

`工程数と例外を見る → 最優先SKUを開く → 担当・期限・不足を確認 → 割当または承認 → 次の担当へ`

### C オーナーパルス

`運用指標を見る → 今日の確認を開く → 原価・送料・長期在庫等の根拠を見る → 人が処理方針を決める → 監査へ記録`

## 共通の変更禁止範囲

- 対象利用者、MVP、販売チャネルの公式経路、安全境界を案ごとに変えない。
- 個人版販売チャネルの自動出品・自動値下げ・無人RPAを示さない。
- AI候補を無確認で確定しない。
- 外注者へ不要な個人情報、取得原価、利益、税務情報を見せない。
- 運用上の売上・粗利を、会計上の利益・所得・税額として表示しない。
- 画像内の細かな文言や仮データを正式仕様として採用しない。

## Slackでの選び方

- `A`: 迷わず始められるホームを標準にする
- `B`: 全工程・例外・担当が見えるホームを標準にする
- `C`: 収益・在庫・未解決が見えるホームを標準にする

組み合わせる場合も、初期表示の主軸を一つ指定する。例: `Bを主軸に、撮影担当だけAの今日の作業カードを使う`。
