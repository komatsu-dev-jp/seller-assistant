# UI方向性の比較

## 結論

現時点の推奨は、AのiPhone撮影・採寸導線を標準にし、BのPC一覧・詳細を組み合わせる案。Cの外注承認モデルはデータ設計へ最初から入れ、画面上の主役にするかはSlack承認で決める。

## 比較

| 項目 | A 安心ステップ | B 高速ワークベンチ | C チーム・リレー |
|---|---|---|---|
| 主役 | iPhoneで1商品 | PCで多数商品 | 外注と承認の受け渡し |
| 初心者の分かりやすさ | 最も高い | 中 | 中 |
| 反復速度 | 中 | 最も高い | 高い |
| 外注対応 | 補助的 | 管理者向け | 最も高い |
| 情報密度 | 低〜中 | 高 | 中 |
| 誤操作防止 | 段階案内で強い | 一括操作の確認が必要 | 承認ゲートで強い |
| 一人運用 | 最も自然 | 慣れると強い | やや過剰 |
| 将来の有料Team差別化 | 中 | 高 | 最も明確 |
| 主な弱点 | 慣れると長い | 初心者には複雑 | 小規模では重い |

## 全案共通の変更禁止範囲

- 個人版メルカリの自動出品・自動値下げ・自動取引を示さない
- AI候補を無確認で確定しない
- 元写真の商品の色、形、傷、しわ、質感を変えない
- 税務の最終判断や申告書作成をAIへ任せない
- 外注者へ不要な購入者情報、利益、税務情報を見せない
- 画像内の文字や数値を仕様として採用しない

## Slackでの選び方

- `1️⃣`: 迷わず使えることを最優先する
- `2️⃣`: 大量処理とPCでの速さを最優先する
- `3️⃣`: 外注・承認・責任の見える化を最優先する

複数案を混ぜたい場合も、まず主軸を1つだけ選び、スレッドへ「Aの撮影 + BのPC一覧」のように修正希望を書く。
