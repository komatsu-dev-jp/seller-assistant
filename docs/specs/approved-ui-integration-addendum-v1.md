## 2. P0で追加する内容

### 2.1 中古1点ものの番号とバーコード

- 中古1点ものでは、画面に見せる商品番号と在庫番号を同じ短い番号にする。
- DB内部ではProductSKUとInventoryUnitを分けたままにし、短い番号は利用者向け表示名として扱う。
- 短い番号は元のチェック値付き在庫番号から一意に復元でき、桁を切り捨てない。4桁未満だけ0で補う。
- A4 24面では、選択した登録済み商品を1商品1枚、重複なしで印刷する。各ラベルへ短い番号、人が読める完全番号、Code 128バーコードを併記する。
- バーコードは現行ラベルの完全番号と版を表す。住所、原価、氏名、認証情報は含めない。
- 手書きラベルを無料の標準として残し、印刷・カメラ読取は任意とする。

### 2.2 スマホで商品を探す

- `商品を探す`と`格納する`を別の目的として表示する。
- スマホで商品バーコードを読むと、権限内の該当商品、状態、現在の保管場所を表示する。
- 読取は検索だけであり、格納、移動、出庫、棚卸、引当を確定しない。
- iPhone Safariのブラウザ標準BarcodeDetectorだけに依存しない。無料のオープンソース読取処理をPWAへ同梱し、カメラ画像をブラウザ内で解析する。
- 読取処理から外部networkへ画像、番号、商品情報を送らない。
- カメラ拒否、非対応、読取失敗時は、チェック値付き完全番号または重複しない短い番号を手入力できる。
- 初回P0はownerとinventory_managerだけに提供する。field_workerへ広げる場合は、期限付き場所割当を検査する最小検索APIを別パケットで追加する。

### 2.3 検品の気になる箇所と全写真

- 気になる箇所ごとに、写真上の位置、場所名、種類、程度、証拠写真、メモ、人の確認状態を関連づける。
- 正面、背面、ブランドタグ、品質表示、気になる箇所を商品単位で一覧にし、残り件数を表示する。
- 原本を上書きせず、外部へ自動送信しない。AIまたは画像処理だけで状態を確定しない。
- 既存の固定pilotを勝手に増やさず、データ構造とpilot影響をSolレビュー後に実装する。

### 2.4 発送前写真の選択

- 工程設定で`高額商品だけ撮る`、`すべて撮る`、`使わない`を選び、高額の目安を利用者が設定する。
- 販売金額が未入力なら注文を止めず、今回だけ撮るか使わないかを人が選ぶ。
- 撮影する場合は商品と梱包状態を非公開原本として保存し、人が確認する。写真だけで発送を自動確定しない。
- 写真は外部サービス、Slack、GitHub、Notionへ自動送信しない。

### 2.5 本人操作の販売調査と注文入力

- 商品情報から検索語をまとめ、本人が編集、コピー、並べ替えできる。
- `メルカリで検索を開く`と`Codex用の質問文をコピー`は、本人が押した場合だけ実行する。検索結果の自動取得、Codexへの自動送信、スクレイピング、Cookie共有を行わない。
- 予想価格は候補として人が入力・確認する。
- アプリ内注文番号は自動発行し、販売先の取引IDと購入者表示名は任意・後入力可とする。不明でも取り出しと梱包を止めない。

## 3. P1のまま固定する内容

- 卸仕入箱の一括登録、箱の見込み・販売後実績・月別KPI、仕入先比較。
- 原本・編集用コピー・加工後・サムネイルの一括編集用ZIP、再取込、自作画像編集。
- 販売状況の定期確認、価格案、返信テンプレートの運用拡張。
- 設定、通知、バックアップ、長期監査の管理画面拡張。

これらのデザイン承認は将来方向の承認であり、現行P0 gateを通る前に機能をONにしない。P1の画面を架空データで見せる場合も、`準備中`または`P0対象外`を明示する。

## 4. 実装順

1. P11: 番号表示、A4 24面Code 128、owner/inventory_manager用スマホ商品検索。
2. P12: 気になる箇所と写真役割のデータ契約をSolレビューし、検品・撮影へ統合。
3. P13: 発送前写真の工程設定、非公開保存、金額未入力時の分岐をSolレビューして統合。
4. P14: 本人操作の検索語・質問文コピー、任意取引ID、用語と固定フッターを整合。
5. P04以降の全自動検証、実画面比較、実利用者pilot、独立Sol最終レビューをやり直す。

## 5. 停止条件

- 外部API、有料サービス、公開、本番操作、PR merge、秘密情報、実個人データが必要になった時点で停止する。
- field_workerの検索権限、写真データ構造、発送状態を画面だけで広げず、contracts/API/DBの拒否条件を先に固定する。
- iPhone実機のカメラ、Code 128、ホーム画面追加、圏外復帰はWindowsで合格扱いにしない。
- 実10商品pilotはP11〜P14のP0差分が凍結した後に行い、古い画面の結果を流用しない。
