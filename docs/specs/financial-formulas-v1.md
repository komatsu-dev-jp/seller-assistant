# 財務計算・会計候補の数式正本 v1

- 状態: 修正版AのSlack承認を反映・Goal再確認待ち
- 更新日: 2026-08-20（JST）
- 数式版: `financial_formula_v1.0.0`
- 対象: P0の運用収益表示、価格下限候補、会計CSV候補

本書はアプリ内の計算方法を一つにそろえるための正本である。会計上・税務上の最終判断や申告額を決める文書ではない。税関連の前提が不明な場合、アプリは推測せず出力を止め、利用者または税理士の確認を求める。

## 1. 共通ルール

- JPYは1円単位の整数で保存・計算し、浮動小数点を使わない。
- すべての計算結果へ`financial_formula_version`を保存する。
- 通貨、税込/税抜/不明、費用負担者、取得元、取得元の金額意味、丸め規則版を事実と一緒に保持する。
- 不明値は0円へ置き換えず`—`と停止理由を表示する。0円は0円と確認できた事実だけに使う。
- 同じ値引、返金、手数料返還、在庫復帰を二度控除しない。
- 運用分析の利益と、会計帳簿上の利益・所得・税額を同一表示にしない。

## 2. 入力事実

| 記号 | 項目 | 説明 |
|---|---|---|
| `Ps` | 注文時商品価格 | 販売者値引前の注文商品価格。取得元が値引後だけの場合は意味を明示する |
| `Ds` | 販売者負担割引 | 販売者の収入を下げる割引 |
| `Dc` | チャネル負担クーポン | 買い手の支払を下げるが、販売者収入を下げないもの |
| `Sr` | 返金前の販売者商品収入 | 取得元が直接示す場合に優先する |
| `Rf` | 成功済み販売者負担返金 | 申請中・取消は含めない |
| `Fc` | 実請求販売手数料 | 手数料返還前 |
| `Fr` | 成功済み手数料返還 | 返金額へ混ぜない |
| `Fp` | 販促・広告費 | 当該取引へ直接紐付く販売者負担額 |
| `Sh` | 販売者負担送料 | 往路・再送を事実別に保持する |
| `Pk` | 梱包費 | 当該取引へ配賦した実額 |
| `Rt` | 返品直接費 | 返品送料、再送等。返金や商品原価と分ける |
| `Cg` | 売却現物の取得原価 | 承認済み配賦額 |
| `Cr` | 再販売可能として在庫へ戻した原価 | 元の取得原価を超えない |

## 3. 取引の計算

1. 買い手の商品支払額候補: `buyer_item_paid = Ps - Ds - Dc`
2. 販売者商品収入候補: `seller_revenue_pre_refund = Sr` が確定していれば`Sr`、なければ `Ps - Ds`
3. 正味商品売上: `net_product_sales = seller_revenue_pre_refund - Rf`
4. 正味販売手数料: `net_sales_fee = Fc - Fr`
5. 純売上原価: `net_cogs = Cg - Cr`
6. 商品粗利益: `product_gross_profit = net_product_sales - net_cogs`
7. 取引貢献利益: `transaction_contribution = product_gross_profit - net_sales_fee - Fp - Sh - Pk - Rt`
8. 商品粗利率: `product_gross_margin = product_gross_profit / net_product_sales × 100`。正味商品売上が0以下なら`—`とする。

取得元がすでに販売者値引後なら`Ds`を再控除しない。取得元が返金後の純額なら、元の売上と返金イベントへ正規化するか差額イベントだけを使い、`Rf`を再控除しない。チャネル負担クーポン`Dc`は販売者収入から控除しない。

## 4. 価格下限候補

価格の自動確定には使わず、人が確認する候補だけを出す。

- `C = 商品原価 + 固定送料 + 梱包費 + 固定手数料`
- `r = 販売価格に対する手数料率`（0以上1未満）
- `T = 目標取引貢献利益`
- 固定額値引`D`を予定する公開価格下限: `ceil(D + (C + T) / (1 - r))`
- 値引率`d`を予定する公開価格下限: `ceil((C + T) / ((1 - d) × (1 - r)))`

手数料率、送料、原価、値引条件のいずれかが不明なら価格下限を確定表示しない。円の公開価格候補は最後に1円単位で切り上げる。

## 5. 月次・仕入先別の運用指標

- 月次区間はJSTの`[月初 00:00, 翌月初 00:00)`とする。
- 売上（運用）: 期間内に取引完了した最終販売額の合計。完了前キャンセルは0。
- 返金: 期間内に返金確定した商品代金。手数料返還を混ぜない。
- 正味売上: `売上 - 返金`。
- 商品粗利益（運用）: `正味売上 - 対応SKUの配賦済み取得原価`。
- 月次取引貢献利益: 対象期間に属する取引ごとの `transaction_contribution`（3章7項）の合計。月次用の別式を定義せず、`net_sales_fee`と販促費`Fp`を含む同じdomain関数を使う。
- 平均仕入単価: `仕入batch総取得原価 / 検収済み点数`。
- 平均販売単価: `取引完了売上 / 取引完了点数`。
- 販売率（仕入cohort）: `基準日時点の返品されていない売却済み点数 / 検収済み仕入点数`。
- 在庫回転率（原価）: `期間売上原価 / ((期首在庫原価 + 期末在庫原価) / 2)`。
- 在庫日数: `平均在庫原価 / 期間売上原価 × 期間日数`。売上原価0なら`—`。
- 売切日数: `取引完了日 - 初回公開日`。中央値とP75を主表示し、未販売品を除外した件数と在庫年齢帯を併記する。
- 返品率（販売cohort）: `返品確定点数 / 配送完了点数`。返品受付期間内は`暫定`。
- 加重値下げ率: `Σmax(初回公開価格 - 最終販売額, 0) / Σ初回公開価格 × 100`。チャネル負担クーポンは除外する。

過去月販売の当月返品は「過去月返品調整」と分離する。月次損益と仕入/公開cohortを混在させない。未販売SKUの原価は在庫へ残す。原価未配賦はランキングから除外し、除外額・件数を表示する。母数`n < 10`は参考値と明示する。

固定注意文: `運用分析の参考値です。会計上の売上・利益・所得・税額を示すものではありません。`

## 6. 会計候補と出力停止

- `accounting_profile`の事業/申告前提、消費税の扱い、インボイス登録、記帳方式は既定`unconfigured`とし、AIが埋めない。
- 勘定科目は、人または税理士が承認した有効な`account_mapping_rule`に一致した場合だけ候補入力する。
- 利用者は候補を採用または変更する。採用者、rule version、原資料、変更理由を保存する。
- profile未設定、rule未一致/期限切れ/競合、証憑不足、貸借不一致、税項目不明、低信頼はCSV出力を停止する。
- Money Forward向けCSVと汎用CSVを別adapterにする。外部APIや自動送信を行わない。
- 同じbatch内の重複はhard blockする。Money Forwardへの再importは新規仕訳を作る可能性があるため、過去batchと同じ対象集合/hashの再出力・再取込は警告、人の明示確認、新batch ID、`supersedes`参照がない限り拒否する。

Money Forward公式importガイド（2026-08-20確認）: https://biz.moneyforward.com/support/account/guide/import-books/ib01.html

CSVの正確な列、serializer、重複規則、fixture/hash: `docs/specs/accounting-export-schemas-v1.md`

## 7. 必須fixture

1. 販売者値引が取得元売上に反映済みで、二重控除0件。
2. チャネル負担クーポンが買い手支払だけを下げ、販売者収入を下げない。
3. 全額返金、一部返金、返金取消、返金後純額の各経路で二重控除0件。
4. 手数料返還が返金へ混ざらず、販売手数料の反対イベントになる。
5. 返品後の再販売可能在庫で原価が在庫へ戻り、商品粗利益から二重控除されない。
6. 未配賦原価、送料不明、税関連未設定が0円化されず、確定/出力を停止する。
7. 価格下限の固定額値引/率値引で切上げが期待値と一致する。
8. `docs/specs/accounting-export-schemas-v1.md` のMoney Forward向け27列/汎用19列schema、fixture、SHA-256、serializer bytes、必須、長さ、日付、円整数、貸借一致が一致する。

すべてのfixtureは同じdomain関数をUI、API、CSVから呼び、独自の再計算を禁止する。
